# FICHE DE TÂCHE : V5-T01 — ENTITÉ PROPERTY, DONNÉES DE DÉMONSTRATION & DOUBLE CONSOMMATION MOBILE

**ID Tâche :** `V5-T01`  
**Version :** V5  
**Priorité :** P1 (MVP Obligatoire — Cœur du flux de bout en bout)  
**Cycle de rotation :** Rotation B  
**Statut :** ⏳ **Planifié**

---

## 1. OBJECTIF
Implémenter la persistance des biens immobiliers dans PostgreSQL, insérer les **4 biens fictifs utilisés comme données de démonstration et de test**, exposer les endpoints `GET /api/v1/properties` et `GET /api/v1/properties/{id}` dans Spring Boot, et connecter les deux applications mobiles (Flutter et React Native) à cette API réelle.

---

## 2. ASSIGNATIONS TRIPARTITES DÉTAILLÉES

### Membre 1 — Backend & Base de Données (Rotation B)
- **Objectif :** Créer le script Flyway `V2__create_property_table.sql` (schéma et insertion des 4 annonces fictives de démonstration), créer l'entité JPA `Property.java`, `PropertyRepository.java`, `PropertyService.java` et `PropertyController.java` implémentant les endpoints validés dans `V5-T00`.
- **Fichiers :** `backend/darlink-backend/src/main/resources/db/migration/V2__create_property_table.sql`, classes Java dans `com.darlink.*`.
- **Tests :** `mvn test` (tests de contrôleur MockMvc et tests de repository).

### Membre 2 — Application Flutter (Rotation B)
- **Objectif :** Implémenter le modèle Dart `PropertyModel.fromJson` strictement conforme au contrat, la source de données distante `PropertyRemoteDataSource` appelant `GET /api/v1/properties`, et connecter l'écran d'accueil pour afficher dynamiquement les biens en provenance de la base avec indicateur de rafraîchissement (RefreshIndicator).
- **Fichiers :** `flutter/services_immobilier_flutter/lib/features/properties/...`.
- **Tests :** `flutter analyze` et test de désérialisation de réponse API.

### Membre 3 — Application React Native (Rotation B)
- **Objectif :** Définir l'interface TypeScript `Property` conforme au contrat, le service d'appel API `propertyApi.getProperties()`, et connecter l'écran d'accueil React Native pour afficher les biens dans une `FlatList` avec gestion du pull-to-refresh (`refreshing` et `onRefresh`).
- **Fichiers :** `react-native/darlink_react_native/src/features/properties/...`.
- **Tests :** `npx tsc --noEmit` et test unitaire Jest du composant de liste.

- [ ] L'application Flutter affiche les annonces récupérées via HTTP/JSON depuis Spring Boot.
- [ ] L'application React Native affiche les mêmes annonces récupérées via HTTP/JSON.
- [ ] Le flux complet de bout en bout (**End-to-End Core Flow**) est 100% opérationnel.
