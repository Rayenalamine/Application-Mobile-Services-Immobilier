# FICHE DE TÂCHE : V3-T03 — SPÉCIFICATION OPENAPI & GESTION D'ERREUR RFC 9457

**ID Tâche :** `V3-T03`  
**Version :** V3  
**Priorité :** P1  
**Cycle de rotation :** Rotation A  
**Statut :** ⏳ **Planifié**

---

## 1. OBJECTIF
Intégrer Swagger UI (`springdoc-openapi`), implémenter la gestion globale et centralisée des exceptions selon la norme **RFC 9457** (`application/problem+json`), et configurer les parseurs d'erreurs correspondants côté Flutter et React Native.

---

## 2. ASSIGNATIONS TRIPARTITES DÉTAILLÉES

### Membre 1 — Application Flutter : Parseur d'erreurs RFC 9457 (Rotation A)
- **Objectif :** Créer la classe d'exception `ProblemDetailsException` dans `flutter/services_immobilier_flutter/lib/core/errors/` désérialisant les champs RFC 9457 (`title`, `status`, `detail`, `instance`) et un widget d'alerte (`SnackBar`/dialogue) affichant le message convivial.
- **Fichiers :** `flutter/services_immobilier_flutter/lib/core/errors/problem_details.dart`.
- **Tests :** `flutter analyze` et test unitaire de désérialisation JSON.

### Membre 2 — Application React Native : Intercepteur d'erreurs RFC 9457 (Rotation A)
- **Objectif :** Créer l'interface TypeScript `ProblemDetails` dans `react-native/darlink_react_native/src/core/errors/` et l'intercepteur Axios capturant les réponses d'erreur pour notifier l'interface utilisateur.
- **Fichiers :** `react-native/darlink_react_native/src/core/errors/problemDetails.ts`.
- **Tests :** `npx tsc --noEmit`.

### Membre 3 — Backend Spring Boot : GlobalExceptionHandler & Swagger UI (Rotation A)
- **Objectif :** Configurer `springdoc-openapi` dans `pom.xml`, créer `GlobalExceptionHandler.java` annoté `@RestControllerAdvice` produisant des réponses `application/problem+json` avec les codes HTTP appropriés, et documenter l'API sur `/swagger-ui.html`.
- **Fichiers :** `backend/darlink-backend/src/main/java/com/darlink/exception/GlobalExceptionHandler.java`, `ApiErrorResponse.java`, `OpenApiConfig.java`.
- **Tests :** Test de contrôleur avec `MockMvc` vérifiant qu'une exception retourne le statut et le format RFC 9457 attendus.

---

## 3. CRITÈRES DE VALIDATION (DoD)
- [ ] Swagger UI est accessible sur `http://localhost:8080/swagger-ui.html`.
- [ ] Une requête vers une ressource inexistante retourne un corps JSON valide selon la RFC 9457.
- [ ] Les deux applications mobiles parsent et affichent correctement le champ `detail`.
